# 원본 전략 연구 구현 계획

연구 목적은 기본 전략의 진입 조건을 개발하고 유전 알고리즘·Optuna로 후보를 탐색한 뒤, 로컬 원본의 판정 기준과 단계로 검증해 실제로 사용할 수 있는 전략을 찾는 것이다.

1. 사용자 제공 로컬 원본·규칙·기존 연구 기록을 확인한다. 원본 신호와 합격 기준을 유지한다.
2. 30M, 1H, 6H, 12H, 1D, 1W를 각각 연구한다. 기존 후보 처리가 끝나면 훈련 구간만 사용해 기본 조건 후보를 개발한다.
3. 원본 순서대로 하드패스 → 개별 트레일링 → 재진입 → 최종 리스크 → 전체 검증 → 봉인 블라인드 → 로컬 쉐도우를 처리한다. 실제 평가 보고서가 있어야 판정한다.
4. GitHub 연구 회차는 프레임마다 330분이다. 입력 데이터 준비를 먼저 끝낸 뒤 연구 시간을 시작하고, 암호화 저장이 성공하면 해당 프레임 다음 회차를 직접 요청한다. 6시간 예약은 복구용이다.
5. 기존 research-state에서 프레임별 research-state-<TF>로 누적 기록을 가져온다. 평가된 통과·탈락의 식별자를 유지해 동일 연구를 반복하지 않는다. 미평가 실행 오류도 보존하고 입력 검증 뒤에만 다시 평가한다.
6. 최종 완료는 기존 로컬 실거래 전략을 동일한 코드 버전·원본 캔들·설정·수수료·평가 구간으로 GitHub에서 재현하고, 신호·거래 내역·손익·검증·쉐도우 판정이 로컬 기준 결과와 일치할 때만 인정한다. 합성 테스트 통과, 기존 보고서 복사, 작업 종료만으로 완료하지 않는다.
7. 본섭 전달은 별도의 생산 환경 계획을 따른다. 현재 원본 서버 전송 보류와 dry-run을 유지하며 실제 주문이나 생산 환경 변경은 수행하지 않는다.

중간 보조 실행기를 추가하지 않고 기존 담당 함수와 연구 워크플로를 수정한다. 블라인드 심볼 선정의 원본 스냅샷 등 필수 입력이 없으면 해당 단계는 대기한다. 기준을 완화하거나 합격 결과를 만들지 않는다.
