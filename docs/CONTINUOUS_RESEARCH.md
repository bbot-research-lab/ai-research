# GitHub 원본 연구 운영

## 실행

Continuous original strategy research의 기본 입력 ALL은 6개 프레임을 준비한다. 공개 OHLCV는 공식 Binance 아카이브와 체크섬으로 검증하고 재사용한다. 완전한 주봉은 실제 일봉 7개에서 집계한다. 부족한 데이터를 평가 실패로 기록하기 전에 입력 검증 단계에서 차단한다.

각 Windows 연구 작업은 원본 roadmap_manager.py와 기존 controller를 330분 동안 실행한다. 실행 종료만으로 전략 합격을 표시하지 않는다. 시간 만료로 중단된 평가는 미완료로 남기고 항상 암호화 체크포인트를 저장한다. 정상 회차와 저장 성공 뒤에는 그 프레임 다음 회차를 요청한다. GitHub 작업 대기·제한·장애로 지연될 수 있으므로 24시간 무중단 실적을 보장하지 않는다.

## 원본과 변경

사용자 제공 규칙과 기존 평가 기준을 유지한다. 기존 72개 기본 레시피 신호가 같은 입력에서 동일함을 확인했다. 추가 조건 후보의 탐색은 원본 하드패스 데이터 중 앞부분 훈련 구간과 원본 simulate를 사용한다. 유전·Optuna 탐색 점수는 합격 판정이 아니다.

원본 연구 함수에 프레임 범위, 기본 조건 개발, 단계 우선 진행, 로컬 쉐도우 연결, 작은 완료 식별자 인덱스를 반영했다. 별도 continue/audit/report 실행기는 주 연구 경로에서 사용하지 않는다. 봉인 블라인드 구간은 프레임별로 겹치지 않게 배정하고 원본 블라인드 판정은 그대로 사용한다.

## 누적 및 재개

원본 입력은 인증된 AES-GCM 암호문 source5.enc로 배포하며 SHA256도 확인한다. 키는 기존 Actions secret BBOT_RESEARCH_STATE_KEY에만 둔다. 결과는 research-state-<TF>에 기존 암호화 저장 방식으로 기록한다. 최초 분리 실행은 누적 research-state를 가져오며 손상된 장부나 지식 파일을 빈 값으로 초기화하지 않는다.

측정된 통과와 실패는 완료 식별자·판정·결과 위치를 유지한다. RUN_STRATEGY_FAIL, SAFE_GRAMMAR_RUN_FAIL, RESULT_NOT_FOUND는 평가 결과가 없는 실행 오류다. 기존 오류 원문은 보존하고 정식 완료 중복 인덱스에서 구분한다. 데이터 검증이 성공한 뒤에만 재개한다. 트레일링·재진입의 미평가 쌍만 기존 담당 함수에서 복구하며 실제 측정 실패와 노출된 블라인드는 재개 대상으로 바꾸지 않는다.

상세 장부의 기존 100,000행 한도와 실패 조회 목록의 1,000행 한도는 유지한다. 별도의 작은 완료·실패 식별자 인덱스와 기존 암호화 객체는 삭제하지 않는다. 이는 중복 연구를 막기 위한 보존 정책이며 무한한 GitHub 저장 용량을 뜻하지 않는다.

## 필수 입력과 본섭

봉인 블라인드의 실제 심볼 적격 스냅샷 state/symbol_universe.json이 없는 경우 원본 선정 단계에서 대기한다. 임의 심볼이나 가상 순위로 대신하지 않는다. 로컬 쉐도우도 원본 minimal_shadow_pass가 확인한 경우에만 합격으로 기록한다. 생산 환경 변경·실제 주문은 수행하지 않으며 B_BOT_V3_SERVER_PUSH_HOLD=1, RUNNER_DRY_RUN=1을 유지한다.

## 검증 범위

로컬에서 원본 연결 테스트 12개, 데이터 준비 테스트 11개, 암호화 체크포인트 테스트 6개를 통과했다. 워크플로 Python 문법과 원본 규칙도 확인했다. 합성 테스트는 실제 전략의 최종 합격 증거가 아니다. 배포 뒤 Actions 실행 로그에서 입력 준비와 연구 진행을 별도로 확인해야 한다.

## 최종 완료 조건: 로컬 실거래 전략 재현

기존 실거래 전략을 로컬과 GitHub에서 같은 코드·캔들·정책 설정·평가 구간·비용으로 재생한다. 입력 및 전략 코드의 해시를 먼저 확인하고 신호, 진입·청산 내역, 손익, 단계별 판정, 쉐도우 판정을 비교한다. 동등성을 확인하지 않은 상태는 최종 완료가 아니다. 연구한 새 전략이 봉인 블라인드와 쉐도우까지 통과한 사실도 실제 실행 증거로 별도로 확인해야 한다.

현재 업로드된 기존 로컬 쉐도우 보고서에는 1H·6H·12H·1D PASS, 30M FAIL이 기록돼 있다. 이는 GitHub에서 새로 재현한 결과가 아니다. 1H와 12H의 보고서에 기록된 전략 소스 해시는 업로드된 소스와 일치한다. 6H·1D는 보고서의 소스 해시와 업로드 파일이 다르고, 업로드 ZIP 및 TAR에는 당시 data/candles 원본이 없다. 그러므로 로컬 재현 동등성은 아직 미검증 상태다. 같은 시점의 실제 사용 코드·설정·캔들·기준 결과 묶음이 필요하다. 부족한 입력을 합성 자료로 대체해 실제 재현 합격으로 기록하지 않는다.

## 실행 오류 복구

첫 실제 실행에서 12H의 개발 탐색 모듈 경로 오류와 6H 재개발 버전의 미평가 트레일링 참조 오류를 확인했다. 소스 루트를 모듈 검색 경로에 먼저 넣고, 재개발 버전도 원본 평가 함수로 지정 쌍을 측정한 뒤 재진입 단계로 진행하도록 수정했다. 30M은 원본이 사용하는 backtest_data 장기 저장 경로에 사전 검증한 같은 캔들을 배치한다. 기존 평가 기준과 30M 전용 원본 라우팅은 유지한다. 중단된 프레임의 암호화 저장은 성공했으며 수정 후 실제 실행 검증이 필요하다.

bbot-small-fixed.zip은 약 1.7MB, 822개 파일이며 누락 목록은 비어 있다. 현재 로컬 코드 확인에는 사용할 수 있으나 원본 캔들은 포함하지 않는다. 6H·1D의 이전 쉐도우 기록과 현재 전략 소스의 해시 차이는 여전히 있어 과거 합격을 현재 버전의 재현 합격으로 사용하지 않는다.
